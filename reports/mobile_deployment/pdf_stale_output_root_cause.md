## 1. Executive Summary

During testing of the newly redesigned PDF generator for the **CRC Multimodal Pathology Edge AI Workstation**, the PDF displayed on the physical phone still appeared as the legacy, compact, single-page log with tiny text and excessive blank space.

A systematic audit across the Android source tree, SQLite database, device storage, and build deployment artifacts identified the **exact root cause**:
1. **Stale SQLite Report Cache Reuse**: `ReportFragment.kt` checked the SQLite report history table (`report_history`) for any existing record associated with the case ID. If a candidate record had an existing file on disk (`File.exists()`), the fragment directly opened that cached file and **completely bypassed** calling `PdfReportGenerator.generateReport()`.
2. **Template Version Stagnation**: Both SQLite historical records and `PdfReportGenerator.kt` shared `TEMPLATE_VERSION = "1.0.0"`. Because there was no template version invalidation, the application treated the pre-existing legacy PDF (`CRC_Report_TCGA-WS-AB45_20261027_161515.pdf`, generated at 16:15 UTC) as fully up-to-date.
3. **Inference Run Decoupling**: Candidate selection did not strictly verify that `candidate.inferenceRunId == currentRun.id`, leading to cross-run cache reuse.
4. **Lack of User-Facing Invalidation/Regeneration**: The report history UI lacked an explicit "Regenerate" mechanism to re-render historical records using updated report templates.

Following the fix, the app was rebuilt, installed on the connected `vivo V2125`, and verified via on-device instrumented execution and PyMuPDF page rendering. The newly generated PDF was inspected and confirmed to match the approved 2-page publication-grade reference design.

### 2.2 Device & Code Artifact Evidence

1. **Stale Cache File on Device**:
   Running `adb shell run-as org.crc.multimodal ls -la /data/user/0/org.crc.multimodal/files/reports/` revealed:
   ```text
   -rw------- 1 u0_a790 u0_a790  358945 2026-10-27 16:15 CRC_Report_TCGA-WS-AB45_20261027_161515.pdf
   ```
   This 358 KB file was generated by the legacy compact generator before the redesign.

2. **Faulty Candidate Selection in `ReportFragment.kt`**:
   ```kotlin
   // PREVIOUS CODE in loadAndCompileReport():
   val existingHistory = repository.getReportHistoryForCase(cCase.id)
   val validCandidate = existingHistory.firstOrNull {
       it.exportStatus != ReportExportStatus.FAILED &&
       it.filePath != null &&
       File(it.filePath).exists() // <-- BUG: No version check, no run ID check, no size validation!
   }
   if (validCandidate != null) {
       activePdfFile = File(validCandidate.filePath)
       // SKIPPED PdfReportGenerator.generateReport()!
   }
   ```

3. **Stale Version Constant**:
   In `PdfReportGenerator.kt`:
   ```kotlin
   const val TEMPLATE_VERSION: String = "1.0.0" // Failed to invalidate existing 1.0.0 records
   ```

4. **Secondary Defect: Raw Monospace Diagnostic Dump**:
   In `PdfReportGenerator.kt`, Section 4 drew `diagSummary` by dumping the raw 22-line terminal output from `InferenceRun.diagnosticsSummary` (`=== RESEARCH ON-DEVICE INFERENCE REPORT ===`). This inflated Section 4 by 260pt and pushed Sections 6 and 7 onto an awkward 3rd page.

## 3. Corrective Actions Taken

### 3.1 `PdfReportGenerator.kt`
- **Bumped `TEMPLATE_VERSION`**: Set to `"2.0.0"`.
- **Atomic File Generation**: Implemented generation via `.tmp_<UUID>` temporary file with `FileDescriptor.sync()`, explicit size check (> 1024 bytes), and atomic rename to target file to eliminate partial/corrupt file reads.
- **Header & Layout Spacing**:
  - Adjusted continuation header padding to `y += 13f` after the top blue bar to prevent header text collision.
  - Adjusted section header spacing to `ensureVerticalSpace(40f); y += 4f; canvas.drawText; y += 10f` to prevent orphan headings.
- **Diagnostic Summary Sanitization**: Condensed multi-line terminal dumps into a clean, professional status line:
  `Execution Status : SUCCESS (Authentic Multimodal Embeddings) · Input Provenance : Authentic Imported Bundle · Integrity Status : SHA-256 Checksums Verified`.
  This retains complete technical traceability while fitting the publication report cleanly into a 2-page layout.

### 3.2 `ReportFragment.kt`
- **Strict Candidate Validation**:
  ```kotlin
  val validCandidate = existingHistory.firstOrNull {
      it.exportStatus != ReportExportStatus.FAILED &&
      it.templateVersion == PdfReportGenerator.TEMPLATE_VERSION &&
      (runEntity == null || it.inferenceRunId == runEntity.id) &&
      it.filePath != null &&
      File(it.filePath).let { f -> f.exists() && f.length() > 1024L }
  }
  ```
- **Dynamic Page Counting**: Replaced hardcoded assumptions with real-time page counting via `PdfRenderer`.
- **Preview Pre-flight Check**: Verified active PDF file exists and has size > 1024 bytes before launching `ACTION_VIEW` intent.
- **History Regeneration Support**: Wired `btnHistoryRegenerate` in `showReportHistoryDialog` to invoke `loadAndCompileReport(forceRegenerate = true)` with `targetRun = runEntity`.

### 3.3 `item_report_history.xml`
- Added `btnHistoryRegenerate` ("Regen") button to history cards, providing users with a one-click way to upgrade older reports to the current template.
